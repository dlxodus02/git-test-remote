# Milestone Guide

팀에서 사용할 기본 마일스톤 기준입니다.

## 추천 운영 방식

- 큰 기능 단위로 마일스톤을 만듭니다.
- 스프린트 단위로 마일스톤을 만듭니다.
- 데일리 이슈는 보통 현재 진행 중인 스프린트 마일스톤에 연결합니다.

## 추천 마일스톤 예시

### Sprint

- `Sprint 1`
- `Sprint 2`
- `Sprint 3`

설명 예시:

```text
2주 스프린트 동안 완료할 백엔드 작업 묶음
```

### Release

- `v0.1.0`
- `v0.2.0`
- `v1.0.0`

설명 예시:

```text
배포 기준 기능 완료와 안정화 작업
```

### Epic

- `Auth`
- `User`
- `Order`
- `Payment`

설명 예시:

```text
도메인 단위 핵심 기능 개발 추적
```

## 이슈 연결 기준

- `Feature` 이슈: 기능이 속한 `Sprint` 또는 `Epic`에 연결
- `Refactor` 이슈: 해당 작업이 반영될 `Sprint`에 연결
- `Daily` 이슈: 진행 중인 `Sprint`에 연결
- `Bug` 이슈: 수정 목표가 있는 `Sprint` 또는 `Release`에 연결

## 시작 추천 세트

처음에는 아래 정도만 만들어도 충분합니다.

- `Sprint 1`
- `Auth`
- `v0.1.0`

## GitHub에서 만드는 방법

1. 레포로 이동합니다.
2. `Issues` 탭을 엽니다.
3. `Milestones`를 클릭합니다.
4. `New milestone`을 누릅니다.
5. 제목과 설명, 마감일을 입력합니다.

## 마감일 추천

- `Sprint` 마일스톤: 스프린트 종료일
- `Release` 마일스톤: 배포 예정일
- `Epic` 마일스톤: 큰 기능 완료 목표일
